A single WebSocket event owner records server acceptance, the original response
and tool-call IDs, pending inputs and automatic continuation. It sends no extra
create request after accepted steering, and never repeats accepted instructions.
On disconnect it retrieves a confirmed terminal response before reconnecting;
accepted but unresolved steering or an unfinished response stops explicitly.
Protocol tests cover these sequences; reconnect tests use controlled transports.
Live evidence establishes steering and its continuation, not a staged outage.
